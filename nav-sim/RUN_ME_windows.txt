KESTREL VOXEL NAVIGATION SIM - Windows build

Double-click  voxel_gui.exe      the simulator: fly a synthetic forest
Double-click  voxel_live.exe     REAL depth: a connected D435i, or a recording


VOXEL_LIVE - the real map and planner over real depth

Runs the SAME VoxelMap and TrajectoryPlanner as the simulator, over frames from
an actual camera. A menu opens: LIVE CAMERA / REPLAY A RECORDING / SIMULATED
FOREST, then START.

There is NOTHING to install for the live camera to work. librealsense is loaded
at runtime, so this exe needs no SDK to have been present when it was built. It
needs realsense2.dll to be findable when you RUN it, which it is if you have
installed the RealSense SDK or the Viewer.

  To check, with no camera plugged in, open PowerShell here and run:
      .\voxel_live.exe --rs-check

  -> "librealsense 2.58.3 (realsense2.dll)"   good, LIVE will be enabled
  -> "could not load librealsense. Tried: ..."  copy realsense2.dll next to
     this exe, or put its folder on PATH. The list tells you where it looked.

In the view:  space pause   v first-person <-> overlay   s save PNG
              m menu        q quit

  DEPTH         what the camera returned. GREY IS NO RETURN, not far away.
  FIRST PERSON  the map from inside. Pale is UNKNOWN, drawn as fog, never air.
  OVERLAY (v)   the same voxels composited ON the depth image they came from.
                If they land on the trunks, the intrinsics, the frame
                convention and the pose all agree. This is the fastest check
                that the whole geometry chain is right.
  MAP SLICE     top-down. Green ring = how far obstacles are MARKED, orange =
                how far free space is CARVED. They are deliberately different.
  PLAN          faint = primitives that are flyable, green = the one chosen.

THE CAMERA IS ASSUMED TO BE HELD STILL. There is no odometry yet, so if you
walk around with it the map will be wrong. That is a missing subsystem, not a
bug in this program.


A menu opens. Click a world, choose Simulated stereo or Perfect (control),
and for the forest choose Open stand or Follow a trail. Then FLY. Keep this
whole folder together - the exe needs the DLLs beside it and reads worlds\
for the Hervanta / Tampere / Helsinki maps.

  IN FLIGHT
    space   pause
    r       restart the same run
    m       back to the menu
    q       quit
    - +     playback speed: 0.25x 0.5x 1x 2x 4x max
    v       FIRST PERSON <-> outside view of the voxel model
    [ ]     view distance of the voxel model: 20 / 32 / 44 / 60 m
    s       toggle voxel-model spin
    <- ->   rotate the voxel model

  WHAT YOU ARE LOOKING AT
    TRUTH + path        the real world, flown trail red, planned path green,
                        forest trails pale blue
    FIRST PERSON        the map from INSIDE, out of the aircraft's own eyes.
                        This is the default top-right pane; v swaps it for
                        the outside view. Pale is UNKNOWN, never empty -
                        where the map is wrong you fly into fog. It looks
                        short because it IS short: at 0.25 m voxels on a
                        12 cm baseline the map can only honestly mark
                        obstacles to about 5 m.
    VOXEL MODEL         the 3D map the aircraft actually built, as solid
                        blocks, with its flown path, its plan and the
                        heading it is currently commanding drawn into it.
                        Block colour is height RELATIVE TO YOU: red is at
                        your altitude and is what you would hit, green is
                        below, blue above.
    VOXEL MAP           a horizontal slice - grey means UNKNOWN, not empty
    DEPTH               what the camera returned; grey = no stereo match

  WORTH KNOWING
    Fly every world TWICE, once on stereo and once on Perfect. If it fails on
    Perfect depth the planner is at fault; if only on stereo, the sensor is the
    limit. That comparison found three real bugs in an afternoon.

    It wanders safely rather than arriving - no configuration reaches its goal
    yet. That is a known open problem, not a broken install.

    This build has no OMPL (no clean Windows port), so the forward planner uses
    a straight-line probe. The reactive layer does the obstacle avoidance and is
    unaffected.

  BATCH RUNS
    voxel_sim.exe is the scriptable version. One run you watched is an anecdote;
    sweep.sh runs every world x every seed and prints a table. Useful flags:

      voxel_sim.exe --world forest --seed 3 --truth --csv run.csv
      voxel_sim.exe --world osm --buildings worlds\helsinki_centre.txt --cell 0.5

    --truth   perfect depth instead of simulated stereo (ALWAYS run this too)
    --seed N  different generated world
    --csv F   per-step log for offline analysis
    --display live view
